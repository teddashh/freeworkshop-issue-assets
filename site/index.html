Discord links expire. Screenshots stay.

連結會過期，截圖不會。

When someone reports a problem in the 自由工坊 Discord, a helper bot drafts a GitHub issue. After the reporter or an admin confirms the draft, the bot strips each screenshot's metadata, commits it here, and links it from the issue.

有人在自由工坊 Discord 回報問題時，小幫手 bot 會先擬好 GitHub issue 草稿。回報者或管理員確認之後，bot 會移除截圖的中繼資料、提交到這個 repo，再在 issue 裡附上連結。

How it works運作方式

Confirmed first, cleaned, filed by path.

先確認、再清理、照路徑歸檔。

The repository holds images only. The bot that files the issues lives elsewhere.

這個 repo 只放圖片，開 issue 的 bot 不在這裡。

01

Nothing lands before a person confirms

有人確認之後才會存進來

The bot drafts the issue in Discord first. Screenshots are committed here only after the reporter or an admin confirms that draft.

bot 會先在 Discord 裡擬好 issue 草稿，等回報者或管理員確認之後，截圖才會提交到這裡。

Discord draft
02

One predictable path per file

每個檔案都有固定路徑

Files land at <owner>/<repo>/<YYYY-MM>/<draft-id>-<n>.<ext>: the repository the issue was filed in, the month, the Discord draft ID, and the screenshot number.

檔案會存在 <owner>/<repo>/<YYYY-MM>/<draft-id>-<n>.<ext>：依序是 issue 所在的 repo、月份、Discord 草稿編號和第幾張截圖。

owner/repo/YYYY-MM/
03

Metadata stripped before upload

上傳前移除中繼資料

Photos can carry EXIF data such as location and device details. The bot strips it before upload, and a check of the stored file on 2026-09-30 found no metadata.

照片可能帶有位置、裝置等 EXIF 資訊。bot 會在上傳前移除；2026-09-30 檢查存放的檔案，沒有找到任何中繼資料。

EXIF

Nothing is public until someone confirms

確認之前都還不公開

A report stays in Discord until a person confirms the draft. Confirming is what lets the screenshot into this public repository.

回報會留在 Discord，直到有人確認草稿。確認這一步，才讓截圖進入這個公開倉庫。

Where each file lands

每個檔案落在哪

Every stored screenshot uses one path. The issue links that path on the main branch.

每張存進來的截圖都走同一種路徑。issue 連的是 main 分支上的那個位置。

Removal移除

Need a screenshot taken down?

需要移除截圖？

Screenshots sometimes show more than intended, such as names, email addresses, or tokens. If a secret was exposed, rotate it first: deleting the image does not undo the exposure.

截圖有時會拍到不該公開的東西，例如姓名、email 或 token。如果外洩的是密碼或金鑰，請先更換：刪掉圖片並不能讓外洩的資訊收回來。

Identify the file

指出是哪個檔案

Note the issue and the screenshot number, or the file path in this repository.

記下是哪個 issue、第幾張截圖，或是這個 repo 裡的檔案路徑。

Ask for removal

提出移除要求

Ask an admin in the 自由工坊 Discord. If you are not in the Discord, open an issue in this repository. Name the file; do not attach the image again.

在自由工坊 Discord 找管理員；不在 Discord 的話，就在這個 repo 開 issue。寫出檔案位置就好，不要再附一次圖片。

The maintainer deletes it

維護者刪除檔案

The file is deleted from main and the issue is edited to drop the link. Older commits still hold the file until the Git history is rewritten.

維護者會從 main 刪除檔案，並編輯 issue 拿掉連結。在改寫 Git 歷史之前，舊的 commit 裡仍然留有這個檔案。

Deleting the file on main

從 main 刪掉檔案

Removal deletes the file from main and drops the issue link. Older commits still hold the file until the history is rewritten.

移除會從 main 刪掉檔案，並拿掉 issue 裡的連結。在改寫歷史之前，舊的 commit 裡還留著這個檔。

Honest status誠實的現況

Where it stands.

目前的樣子。

Set up in September 2026. So far it holds one screenshot, from a closed test issue.

2026 年 9 月建立，目前只存了一張截圖，來自一個已關閉的測試 issue。

Works today

目前可用

  • Screenshots stored by path and linked from issues through raw.githubusercontent.com
  • 截圖依路徑存放，issue 透過 raw.githubusercontent.com 連結
  • EXIF stripped before upload; the stored file had no metadata when checked on 2026-09-30
  • 上傳前移除 EXIF；2026-09-30 檢查存放的檔案，沒有任何中繼資料
  • This project page publishes only site/, never the stored images
  • 專案介紹頁只發佈 site/，不會發佈存放的圖片

Limits and not yet

限制與尚未完成

  • The repository is public, so a confirmed screenshot is public too. Confirming the draft is the privacy check
  • repo 是公開的，確認過的截圖也就公開了；確認草稿那一步，就是隱私把關
  • Deleting a file breaks the issue's image link but does not erase it from Git history
  • 刪除檔案會讓 issue 裡的圖片連結失效，但不會把它從 Git 歷史裡抹掉
  • The bot's code is not in this repository
  • bot 的程式碼不在這個 repo 裡
